# Switch Lang

Локальная утилита RU ↔ EN для macOS на Apple Silicon на **Swift + AppKit**. Accessibility, Carbon и IOKit вызываются непосредственно из Swift; внешних библиотечных зависимостей нет. Небольшой C11-адаптер предоставляет только lock-free 64-битные атомики для macOS 11, без прикладной логики. Отдельный прежний Objective-C-инструмент подписи остаётся сборочным инструментом, не частью приложения.

Это первая экспериментальная версия, не полноценная замена Punto Switcher. Проверяйте её на синтетическом тексте: совместимость с конкретными редакторами и безопасность всех сценариев ввода ещё не подтверждены.

## Возможности

- Преобразование соответствующих клавиш русской ЙЦУКЕН и английской QWERTY с сохранением регистра.
- Исправление последнего набранного слова настроенной клавишей, включая одиночный Caps Lock.
- Автоматический режим с небольшим встроенным списком частых слов: неоднозначные и неизвестные слова пропускаются.
- Все разделители слов: пробельные символы, пунктуация и другие небуквенные границы. Сам разделитель сохраняется.
- В автоматическом режиме Return, Enter цифрового блока и Tab при готовом кандидате программно откладываются: сначала исправление слова, затем обычное действие клавиши. Удерживать клавишу пользователю не нужно.
- Меню macOS, настройка клавиши, ручной режим при первом запуске и явная пауза.
- В обоих режимах замена клавишами: Backspace → переключение раскладки → набор соответствующих физических клавиш. AX используется только для проверок, не для записи текста или выделения.
- Без буфера обмена, сети, журнала набора, нейросетей и периодического опроса.
- Отключаемый технический файловый лог для диагностики Caps Lock и отказов AX; по умолчанию выключен.

Поддерживаются системные источники ввода **ABC / U.S.** и **Russian**. В macOS Russian `ё`/`Ё` соответствуют английским `\`/`|`, а не PC-клавише с обратной кавычкой. Russian — PC, раскладки сторонних разработчиков и методы композиционного ввода не поддерживаются.

## Сборка

Нужны Mac на Apple Silicon, Command Line Tools со Swift 6.4.2 / `swift-format`, Python 3.9+ и системный Clang. Компиляция использует режим языка Swift 5 и deployment target macOS 11.0; это цель сборки, а не подтверждённая проверками совместимость со всеми версиями macOS. Rust и Cargo больше не нужны. Кеши, временные файлы и самостоятельные бинарные файлы находятся в игнорируемом `.tools`, глобальная установка не меняется.

```sh
./scripts/test.sh
# Только для нового workspace без существующей идентичности:
python3 -B scripts/sign-app.py init
# При обновлении сохраните существующий .tools/signing и завершите GUI через меню.
./scripts/build-app.sh
open "dist/Switch Lang.app"
```

`Sources/SwitchLang` содержит чистый конвертер/детектор/кандидат, AppKit-интерфейс, отдельные listener и processing thread, AX-проверки, клавиатурную транзакцию и диагностику. `Tests` — синтетические проверки без захвата ввода и реальных запросов разрешений. `scripts/build-swift.sh` собирает отдельный release-бинарный файл в `.tools/build/release`; `--debug`, `--sanitize=address` и `--sanitize=thread` создают отдельные проверочные сборки. Для диагностических тестов используются только синтетические числовые записи в `.tools`.

`scripts/build-app.sh` собирает release-приложение с постоянной локальной сертификатной подписью. Без подготовленной идентичности сборка завершается ошибкой, не создаёт новый ключ и не возвращается к ad-hoc. Полностью подписанный и проверенный пакет сначала готовится во временном каталоге; прежнее приложение не заменяется при ошибке сборки/подписи. Запущенный `switch-lang` требуется завершить. Результат — `dist/Switch Lang.app`; установка в `/Applications` не требуется.

### Постоянная локальная подпись

`python3 -B scripts/sign-app.py init` создаёт отдельную связку `.tools/signing/local-signing.keychain-db`, сертификат и случайный пароль в игнорируемом `.tools/signing`. Повторная команда проверяет существующую идентичность, а не перевыпускает её; повреждённое/неполное хранилище вызывает ошибку. Каталог имеет права `0700`, файлы `0600`. Приватный ключ импортируется с доступом для `/usr/bin/codesign`; временные зашифрованные PEM/P12 удаляются. Пароль не передаётся аргументом или переменной окружения. Связка закрывается после команды; дополнительно настроены блокировка при сне и автоинтервал пять минут. Это защита учётной записью и правами файлов: пароль открытия хранится рядом, процессы с доступом к этим файлам не изолированы.

Сохраняйте весь `.tools/signing` в защищённой резервной копии и не публикуйте его. Удаление каталога с последующей инициализацией или истечение десятилетнего сертификата потребуют новой идентичности и повторной настройки разрешений. Сборка проверяет срок сертификата, ключ и соответствие подписи. Идентификатор `local.switch-lang.app` и требование `identifier … and certificate leaf = H"…"` остаются постоянными; `cdhash` каждой изменённой сборки закономерно меняется.

Системное доверие, login/System keychain и постоянный список поиска связок не изменяются. `codesign --keychain` выбирает ключ из связки проекта; при построении цепочки сертификатов сам `codesign` также может читать обычный список связок. Это не Developer ID, notarization или подпись для распространения другим пользователям.

При первом переходе со старой ad-hoc подписи разрешения нужно один раз выдать новой идентичности средствами macOS. Сборка не сбрасывает и не выдаёт их автоматически. Одинаковая идентичность двух разных подписанных пакетов проверена. При одном реальном обновлении прежнего Rust/Objective-C GUI на Swift GUI на этой машине сохранились эффективные Accessibility/Input Monitoring и включённый клавиатурный tap, без сброса TCC. Это не гарантия любых будущих обновлений и не подтверждение строки в системном списке.

## Первый запуск

1. Запустите собранное `.app`. В строке меню появится `RU⇄EN`.
2. При первом запуске новой схемы приложение само запрашивает каждый недостающий доступ через macOS: Accessibility нужен для проверки поля и эмуляции исправления, Input Monitoring — для событий клавиатуры. Вручную искать `.app` для запуска запроса не нужно. Подтвердите Switch Lang в системном диалоге или соответствующем разделе настроек; выдать разрешение может только пользователь. Уже выданные доступы не запрашиваются.
3. После изменения разрешений нажмите «Проверить доступ» в настройках приложения или меню; если macOS требует, перезапустите приложение.
4. В настройках назначьте клавишу. По умолчанию клавиша не назначена, режим ручной. Можно записать обычную клавишу, сочетание с Command/Control/Option/Shift или одиночный Caps Lock. Остальные одиночные модификаторы и медиасобытия не поддерживаются; Esc отменяет запись.
5. В обычном проверяемом текстовом поле наберите `ghbdtn` в ABC и нажмите назначенную клавишу. Ожидается `привет` и русская раскладка. Обратный пример — `руддщ` в Russian → `hello`.
6. Автоматический режим включайте отдельно и сначала проверяйте на несекретном тестовом тексте.

Попытка каждого автоматического запроса запоминается **до** его вызова: после отказа, перезапуска, отзыва доступа или сброса режима/клавиши повторных автозапросов нет. При обновлении со старого приветствия регистрация выполняется один раз независимо от прежней отметки. Если приложение завершилось между двумя запросами, не начатый второй остаётся допустимым при следующем запуске. Системными окнами и появлением строк в списках управляет macOS: AX-запрос асинхронный, приложение не предполагает последовательного закрытия диалогов и не гарантирует принудительное добавление записи.

Кнопки **«Универсальный доступ…»** и **«Мониторинг ввода…»** в настройках и меню всегда открывают свой раздел macOS. При отсутствии доступа кнопка сначала повторяет только его системный запрос; второе разрешение не затрагивается. Уже выданный доступ не запрашивается, но открыть его раздел можно. Статусы перепроверяются при открытии меню и возвращении в окно настроек, без опроса по таймеру. Ошибка открытия показывается с ручным путём к разделу. Успешная передача ссылки системе не подтверждает нужный экран или выдачу доступа и не запускает обработчик: после подтверждения нажмите **«Проверить доступ»**. Повреждённые настройки сначала требуют явного сброса. Тесты и диагностические команды не вызывают запросы и не меняют разрешения.

Не запускайте несколько экземпляров одновременно: системные события и настройки могут конфликтовать. Не удаляйте хранилище постоянной подписи при обычном обновлении; смена идентичности требует повторных разрешений.

Настройки режима, клавиши, диагностического лога и Boolean-отметки попыток `accessibilityRegistrationAttempted` / `inputMonitoringRegistrationAttempted` сохраняются стандартным механизмом macOS в домене `local.switch-lang.app`; старый `permissionIntroductionHandled` сохраняется для совместимости. Введённый текст туда не записывается. Тесты и диагностические команды пользовательские настройки не меняют.

## Диагностический лог

В настройках есть переключатель **«Диагностический лог в файл»**, по умолчанию выключенный, и кнопка **«Показать файл»**. Состояние переключателя сохраняется между запусками. Повреждённое значение этой необязательной настройки отключает только журнал, не ручное исправление.

При включении создаётся `switch-lang.log` рядом с `.app`; для сборки в этом workspace это `dist/switch-lang.log`. Ротация ограничивает текущий файл и одну копию `switch-lang.log.1` размером до 1 МиБ каждый. Файлы создаются с правами `0600`; неподходящий тип файла или символьная ссылка не используются. Если каталог недоступен для записи, ошибка показывается в настройках, без переноса журнала в другое место и без остановки исправления.

Сохраняются только монотонное время, фиксированный этап и числовой технический код: наблюдение Caps-состояния, подготовка и подтверждение сброса, передача ручной команды, отказ проверки AX-контекста и результат замены. Уведомление о выключенном Caps может быть собственным сбросом и не считается отдельным физическим нажатием. Текст, символы и коды обычных клавиш, значения AX-полей, названия окон, пути документов и имена приложений в лог не передаются. Обычный набор не журналируется: последний исход проверки контекста хранится одной числовой меткой и попадает в файл только при ручной команде. Одинаковые результаты повторной настройки Caps не записываются на каждую обычную клавишу.

Обработчики передают числовые записи в ограниченную очередь на 128 элементов без ожидания; дисковые операции выполняет отдельная последовательная очередь. При перегрузке записи пропускаются, их число отмечается в журнале. Выключение прекращает запись и закрывает файл после слива принятых записей; существующие файлы не удаляются. Сброс настроек также выключает журнал. Ошибка журнала не ставит исправление на паузу.

Коды `manual.received` и `manual.no_candidate` описывают последний исход отслеживания: `0` — ввода не было, `1` — сброс, `2` — просроченное событие, `3` — разрыв поколения, `4` — навигация/сочетание, `5` — отказ контекста, `6` — смена фокуса/раскладки, `7` — неподдержанная раскладка, `8` — нет переведённого символа, `9` — неверный Unicode, `10` — служебная клавиша, `11` — ввод наблюдался, `12` — Backspace, `13` — изменился подтверждённый якорь, `14` — предыдущая замена уже потребила кандидат. Это числовая метка, не содержимое ввода.

Код зависит от этапа. Для `caps.controller_open`, `caps.read` и `caps.clear` это результат IOKit. Для проверок контекста и замены ошибки AX/OSStatus сохраняются как есть, собственные причины имеют фиксированные положительные коды: например, `23` — якорь не подтверждён, `24` — каретка изменилась, `26` — изменился числовой счётчик символов, `27` — диапазон вышел за подтверждённую строку. Этап `replacement.position_verification` подтверждает только позицию/счётчики, не содержимое поля. Проверки и числовые причины находятся в [AXContext.swift](Sources/SwitchLang/AXContext.swift) и [ReplacementExecutor.swift](Sources/SwitchLang/ReplacementExecutor.swift). У этапов сброса `1` означает начальную настройку, `2` — команду.

Для диагностики включите лог, вручную наберите синтетическое слово и нажмите Caps Lock, затем выключите лог. Если нет этапов наблюдения Caps, это ещё не доказывает отказ AX; если есть передача команды, следующие этапы помогут отделить пустой кандидат, устаревший ввод, недоступный атрибут и неподтверждённую каретку. Наличие диагностического лога само по себе не означает исправления дефекта Caps Lock.

## Caps Lock

1. В настройках клавиатуры macOS **выключите системное переключение источников ввода клавишей Caps Lock**. Приложение не меняет эту настройку и не гарантирует подавление системного обработчика, если она включена.
2. В настройках Switch Lang включите запись и нажмите Caps Lock без других модификаторов; подтвердите назначение.
3. При активной работе приложения Caps Lock — только ручная команда. Без безопасного слова замены не будет. После успешной замены приложение по-прежнему выбирает целевую раскладку, а не выполняет обычное системное переключение Caps Lock.

При назначении и возобновлении работы исходное состояние Caps Lock сбрасывается в выключенное. Используются публичные IOKit Get/Set с проверкой результата, без глобального переназначения клавиатуры и постоянных изменений macOS. Только подтверждённый переход включено → выключено допускает команду; уведомление об уже выключенном состоянии не исправляет повторно. Сброс выполняется вне callback на listener run loop, поэтому следующий ввод может кратко ожидать; задержка ещё не измерена. Запоздавший Caps-флаг в доставляемых событиях снимается с сохранением остальных модификаторов. Отсутствие краткой вспышки индикатора не гарантируется.

Get/Set не образуют атомарную операцию; проверки уменьшают, но не исключают гонку со сменой контекста. Ошибка открытия, чтения, сброса или подтверждения состояния вызывает явную паузу, а не ложное сообщение об исправлении. Слишком короткое нажатие Caps Lock macOS может отфильтровать ещё до event tap. На паузе, во время записи клавиши, при Secure Input, отключённом обработчике или после выхода Caps Lock имеет обычное системное поведение. Реальные нажатия, удержание, индикатор и отсутствие системного переключения языка требуют отдельной проверки на вашей клавиатуре; синтетические тесты этого не доказывают.

## Ограничения и защита текста

- Исправляется только кандидат, собранный из текущих событий набора: не выделенный текст и не произвольное старое слово перед кареткой. Последнее слово и хвост разделителей хранятся только в оперативной памяти. Текст приложения, выделенный текст, суффикс и соседние символы не читаются.
- По явному выбору пользователя сверки содержимого нет. Если редактор сам изменил слово, буфер клавиатуры может перестать ему соответствовать даже при прежней каретке и длине. В этом случае возможно удаление другого текста; метаданные не дают гарантии совпадения содержимого.
- Отслеживаются только буквы RU/EN: пунктуационные клавиши, соответствующие русским буквам, полностью покрыты чистой таблицей преобразования, но не всегда образуют отслеживаемое слово в системном вводе. Поэтому некоторые слова с `ж`, `э`, `х`, `ъ`, `б`, `ю`, `ё`, набранные в EN, будут пропущены или разделены.
- Числа, чужие алфавиты и маркеры `@`, `/`, `\`, `_`, `=` блокируют кандидат до следующего пробельного символа. Это защита, а не полное распознавание кода, URL и адресов: точка и дефис могут быть и пунктуацией, и частью идентификатора.
- Слово ограничено 64 символами, хвост разделителей — 16. Превышение лимита сбрасывает кандидат, а не обрезает его до исправляемого фрагмента.
- Перемещение каретки, щелчок мыши, выделение, постороннее сочетание с Command/Control/Option/Fn/Help, смена поля или раскладки, устаревшие события и переполнение очереди инвалидируют кандидат. Нажатие модификатора само по себе сохраняет якорь для возможной команды исправления; перед удалением модификаторы и клавиша команды должны быть отпущены. Ожидание событийное и ограничено подготовкой в 200 мс, для отложенного Enter/Tab — его оставшимся бюджетом. Новый ввод отменяет подготовку; глобальные отпускания модификаторов не синтезируются. При обычном включённом Caps Lock безопасная подготовка также может быть пропущена.
- До подтверждения незащищённого редактируемого поля Unicode не извлекается: системный callback передаёт только ограниченные метаданные клавиш. При Secure Input события не обрабатываются; неподдерживаемые поля пропускаются.
- Обычные разделители передаются сразу; коррекция ожидает подтверждённой числовой позиции кандидата через AX-события. Для Return, Enter цифрового блока и Tab есть отдельный путь: при заранее распознанном автоматическом кандидате сохраняется исходный key-down, позиция кандидата проверяется и слово заменяется **без добавления** `\n`/`\t`, затем клавиша передаётся редактору. Shift и обычный Caps Lock сохраняются (кроме Caps Lock, назначенного командой исправления); сочетания с Command/Control/Option/Fn/Help, повторы, ручной режим и отсутствие готового кандидата обходят этот путь.
- Отложенный путь включается после пробной доставки служебного null-пробуждения текущему tap. Без неё Enter/Tab не перехватываются. До удаления новый ввод или истечение целевых 100 мс отменяет подготовку: сохранённая клавиша передаётся перед новым событием. При безопасном отказе обычное действие сохраняется. Если worker ещё не распознал слово, исправление может быть пропущено.
- Единая клавиатурная транзакция для обоих режимов выполняется на listener run loop вне callback. Swift worker эксклюзивно передаёт AX-контекст и ждёт завершения; последующие физические события в это время остаются у macOS. Частной FIFO набора нет, proxy не сохраняется. Главный поток только готовит таблицу/события и переключает TIS; отменённый ожидающий main-block не переключает раскладку. Его единственный слот удерживается до подтверждения очистки самим блоком: зависший main loop не накапливает отменённые снимки набора. Ожидания main/AX-подтверждения конечны; опроса по таймеру и задержки между каждой парой клавиш нет.
- До первого Backspace выделяются все события удаления, набора и отпускания, проверяется точная воспроизводимость символов под целевой таблицей. Число Backspace включает слово и уже введённые разделители, но не отложенный Enter/Tab. Исполнитель принимает только одиночные BMP-буквы и простые ASCII-разделители: управляющие символы, суррогатные пары, композиция и неподдержанный целевой клавишей разделитель отклоняются **до удаления**, без Unicode/clipboard fallback. Это ограничение системного исполнителя, не изменение чистого преобразования или правил распознавания границы слова.
- Нужны подтверждённые незащищённые `AXTextField` / `AXTextArea`, чтение только метаданных `AXSelectedTextRange` и `AXNumberOfCharacters` через типизированный список разрешённых атрибутов. `AXStringForRange`, чтение значения и выделенного текста не используются. `AXFocused` всегда должен быть Boolean `true`. Для `AXTextArea` допускается только явный отказ `attributeUnsupported` при чтении `AXEnabled`: проверенный AppKit `NSTextView` не предоставляет этот атрибут. Для `AXTextField` исключения нет; поддержанное `false`, отсутствие значения, неверный тип и другие ошибки блокируют исправление. Обычная редактируемость подтверждается доступностью записи `AXValue` либо `AXSelectedText`, но содержимое этих атрибутов никогда не читается и не записывается. Изменяемость диапазона выделения не требуется. Только чтения роли недостаточно: readonly-поле может трактовать Backspace как навигацию. Для `AXTextArea` именно Apple Terminal добавлен отдельный путь: проверяется действующая Apple-подпись процесса с identifier `com.apple.Terminal`, а не одно имя приложения. Обе AX-возможности записи должны успешно вернуть `false`; ошибки API не превращаются в разрешение. Другие readonly-поля, терминалы и нестандартные роли по-прежнему запрещены.
- Путь Terminal дополнительно требует `AXInsertionPointLineNumber` и `AXRangeForLine`: пустая каретка находится в одной неизменной строке, числовые диапазоны укладываются в размер экрана. Содержимое строки и её правый хвост не читаются. Позиция до ввода запоминается по событиям фокуса/сброса/AX, затем ожидаемая каретка изменяется только согласно отслеженному набору и Backspace; уже начатый ввод нельзя задним числом привязать к новому якорю. Удаление за исходный якорь делает это подтверждение недействительным. Без продвижения каретки скрытый набор не разрешает удаление. Без исходного якоря, при выделении, изменении строки или переносе слова на другую экранную строку исправление пропускается.
- В Terminal `AXNumberOfCharacters` описывает экран/scrollback и может сохранять стёртые ячейки как пробелы. Поэтому логическая длина текущего ввода проверяется по подтверждённой каретке; исходный экранный счётчик хранится отдельно. После удаления допускается только прежнее экранное число либо его уменьшение ровно на длину удалённого слова; до удаления и после окончательного набора число должно совпасть точно. Это не доказательство совместимости со всеми shell/TUI и не гарантия атомарности при внешнем выводе.
- Перед удалением проверяются фокус, пустое выделение, числовые границы диапазона, подтверждённая каретка и поколение; слово берётся только из клавиатурного буфера. Суффикс, соседние символы и граница слова в приложении не сверяются. Сначала посылаются Backspace в проверенный PID; их результат подтверждается кареткой и уменьшением числа символов. Затем переключается источник, повторно проверяются позиция после удаления, пустая каретка и число символов, набираются физические клавиши с явными Shift down/up и проверяются каретка, раскладка и исходное число символов. Обычная автокоррекция использует AX-уведомления; подтверждения ждут событий и одного финального deadline, без повторного удаления/набора. Совпадение чисел не доказывает правильность полученного текста.
- 100 мс — целевой бюджет подготовки Enter/Tab, не жёсткий предел всей транзакции. Ожидание каждого main-запроса и каждой стадии AX-подтверждения ограничено 100 мс; сами системные вызовы могут завершиться позднее. Публикация `CGEvent` не подтверждает его доставку. Проверки уменьшают, но не исключают гонки со сменой поля/каретки, внешней правкой и отключением tap; адресация PID не закрепляет конкретное поле внутри приложения. Доставка, downstream-порядок и задержки ещё требуют реальной проверки.
- После частичного или неподтверждённого удаления/набора включается фиксированная пауза: проверьте текст перед явным снятием. Обновление меню её не отменяет. Нет повторов, rollback или скрытого Undo. **Отложенный Enter/Tab при таком отказе не передаётся**, чтобы не отправить повреждённый текст; при работающем tap связанное отпускание и автоповторы подавляются. После потери tap перехват следующих физических событий недоступен. После успешного подтверждения исходный key-down передаётся в тот же PID ровно один раз, обычный key-up не синтезируется. Без начавшегося удаления действие сохраняется, включая cleanup при выходе. Если отменяющее null-пробуждение не доставлено, действует прежний одноразовый резерв 10 мс. Уже переданные без задержки Enter/Tab сбрасывают кандидат; задним числом исправления нет.
- При отключении event tap работа останавливается до явной проверки доступа пользователем; нет автоматического бесконечного перезапуска.

Непрерывная Terminal-регрессия запускается отдельно: `python3 -B scripts/test-terminal-integration.py --owned-fixture`. Нужны уже выданные разрешения, подписанный пакет и запущенный Terminal. Создаётся собственный native TTY-редактор без shell; два слова исправляются по разные стороны Return без промежуточного сброса и ожидания AX. Диагностический пакет временно занимает прежний путь с прежней подписью, затем восстанавливаются оригинал и состояние GUI. Успех требует 2/2 результатов и проверки неизменных пакета, настроек и исходников; артефакты остаются в уникальном `.tools/terminal-integration-*`. Это адресный адаптер, не проверка физической клавиатуры/session tap.

`test-signing.py` требует предварительного `init`: проверяет закрытые права, отказ без ключа до Swift-сборки/замены приложения, отсутствие перегенерации, блокировку параллельных операций и подпись двух разных синтетических `.app`. Их `cdhash` различны, взаимные требования одинаковы; чужая ad-hoc подпись и изменённый после подписи пакет отклоняются. Тесты не запускают GUI, не запрашивают и не сбрасывают TCC.

`test.sh` сначала проверяет запрет AX-чтений содержимого и саму эту source-policy, затем выполняет строгий `swift-format`, компиляцию с warnings-as-errors, self-test, тесты диагностического лога и инструмента подписи. `--test-logging` проверяет изолированный журнал с синтетическими записями в `.tools`. `--self-test` проверяет чистое преобразование и отслеживание, очередь/атомики, синтетические системные значения, настройки/разрешения, Caps Lock, отложенные клавиши и клавиатурный план: обе стороны, регистр, разделители, лимиты, сбои выделения ресурсов, полное освобождение, порядок down/up/Shift и отмену без публикации событий. Отдельно проверяются отменённый main-request, запрет позднего начала, событийный допуск отпусканий и подавление Enter/Tab при неопределённом результате. Создаваемые CGEvent не публикуются; работа tap, реальные AX-уведомления, shutdown и чужие приложения этим не подтверждаются. `--check-layouts` читает включённые системные таблицы, сравнивает 66 соответствий и буквенные клавиши с Caps Lock/Caps Lock + Shift; строит неопубликованные планы в обе стороны, в том числе с регистром и разделителями. Набор не перехватывается, раскладки не переключаются. Обе поддержанные раскладки должны быть включены в macOS.

`--diagnose` читает состояние разрешений и Secure Input без запросов доступа и без перехвата ввода. Это контекст запускаемой CLI-команды, не доказательство разрешений отдельно запущенного GUI. `--benchmark` измеряет только чистый детектор на синтетических словах, а не задержку исправления в редакторе, CPU фона или полную память приложения.

Приёмка реальной интеграции выполняется отдельно: фокус и каретка, защищённые поля, Enter/Tab, Caps Lock (исходно включённый/выключенный, повторные нажатия и удержание, пауза, системное переключение языка), вставка, Undo, быстрый набор, отзыв разрешений и разные приложения. Результаты и ограничения необходимо связывать с конкретной сборкой и машиной.

## Проверки переноса на Swift

На macOS 27.2 / SDK 27.2, Apple M1 Pro, 32 ГиБ RAM, Swift 6.4.2 (режим Swift 5):

- Совместная debug/release-сборка с warnings-as-errors и строгий `swift-format` проходят; Mach-O содержит arm64/macOS 11.0.
- Self-test покрывает чистое ядро, строгие настройки/регистрацию разрешений, Caps, планы клавиш, action/deadline/latch/main-request, UTF-16, очередь и атомики. Отдельно проходят 211 проверок логгера и 12 проверок инструмента подписи.
- Полные Swift self-test и лог-тесты прошли под AddressSanitizer и ThreadSanitizer. На macOS leak-check ASan не включался. Эти прогоны не создают tap, не публикуют клавиши и не меняют пользовательские defaults/TCC.
- Разовая дифференциальная проверка Rust ↔ Swift: 1 112 064 Unicode scalar, четыре исхода отслеживания/Backspace/action для каждого — различий нет. Read-only системная проверка подтверждает 66 соответствий, Caps/Shift и неопубликованные планы.
- Прежние исходники, настройки сборки и пакет сохранены в игнорируемом `.tools/swift-migration-before`; активная сборка Rust/Objective-C удалена после побайтовой сверки архива. Используется прежняя идентичность `local.switch-lang.app` и существующий сертификат; новые ключи для рабочей идентичности не создавались.
- Подписанный Swift-пакет опубликован в `dist/Switch Lang.app`; строгая проверка подписи с прежним certificate-pinned DR, упакованный self-test и таблицы проходят. У запущенного Swift GUI TCC подтвердил Accessibility и ListenEvent (`authValue=2`), создан один включённый клавиатурный tap. Семь настроек до/после совпали: ручной режим, Caps Lock, включённый лог и три permission-маркера сохранены; TCC не сбрасывался. Дополнительное штатное завершение Swift GUI и повторный запуск прошли, настройки и tap сохранились. Активная замена во время завершения не проверялась.
- Независимые статические ревью runtime/AX/исполнителя и UI/настроек/логгера не выявили подтверждённых P1/P2; это не сквозной GUI-тест.
- Один release-прогон синтетического детектора: 20 000 вызовов для `ghbdtn`, `руддщ`, `hello`, без отдельного прогрева, `DispatchTime.uptimeNanoseconds`; p50 1375 нс, p95 1750 нс, p99 1833 нс. Это не задержка исправления или измерение CPU/RSS; прямое сравнение с прежним Rust-прогоном с другими часами/условиями не выполнялось.
- Выборочный `sample` работающего Swift GUI в простое, 1 секунда / интервал 1 мс: main/listener ожидают run loop, worker — семафор очереди; physical footprint в отчёте `14.3M`. Это единичный снимок, не ресурсная приёмка и не сравнение с прежней версией. Метаданные latency из `CGGetEventTapList` не принимаются за задержку исправления.

Эти проверки переноса сами по себе не подтверждали реальное исправление текста. Последующая изолированная проверка описана ниже. Активная замена при shutdown, физический Caps Lock, Undo, отзыв доступа, полные ресурсные бюджеты и работа в пользовательских редакторах пока не подтверждены. Перепись не считается исправлением ранее отсутствовавшей строки «Мониторинга ввода»; её текущее наличие и причина прежнего перехода denied → granted остаются неизвестны.

## Исправления интеграции ввода

История версий до отказа от чтения содержимого; проверка нового контракта приведена в следующем разделе.

На той же машине воспроизведены и исправлены два отказа:

- Стандартный AppKit `NSTextView` возвращал `attributeUnsupported` (`-25205`) для `AXEnabled`; прежняя обязательная проверка запрещала замену до удаления. Совместимость ограничена `AXTextArea` и не отменяет проверки фокуса, защиты, редактируемости и точного диапазона.
- Одно переключение TIS присылало повторные уведомления выбранного источника. Первое погашало ожидание, второе инвалидировало поколение и вызывало защитную паузу даже после правильного набора. Теперь во время активного, неотменённого переключения/подтверждения каждое такое уведомление заново сверяет фактическую целевую раскладку. Другая или неизвестная раскладка, смена списка источников и уведомления вне операции не получают этого исключения.

Обе причины закреплены регрессиями: тесты падали до исправлений и прошли после. Изолированный сквозной прогон подписанного прежним сертификатом диагностического GUI завершил **16 из 16 сценариев**: контроль адресной доставки; ручные `ghbdtn` → `привет` и `руддщ` → `hello`; начальный регистр и завершающий пробел; автоматический пробел в обе стороны; Return/Tab в обе стороны и Enter цифрового блока с одним действием после исправления; отказ после смены поля, в readonly-поле и при выделении; синтетическая Caps-команда с подтверждённым сбросом HID-состояния. Редактор сверял точный UTF-16, неизменность второго поля и порядок действия; успешные замены также подтверждались рабочими AX-проверками. Защитные отказы readonly/выделения подтверждены этапами лога, не только отсутствием изменения текста.

Использован только собственный ограниченный AppKit-редактор с синтетическим текстом. Рабочие handler, worker, AX и клавиатурный исполнитель сохранены; диагностическая копия сигнатуры допускает `nil` proxy для адресного адаптера, тело обработчика не изменено. Это **не проверка физических клавиш или перехвата исходным session tap**, не приёмка сторонних редакторов и не замер задержки: время наблюдения включает IPC и тестовые паузы. Настройки, сертификат и TCC не менялись; после каждого диагностического запуска исходный пакет восстанавливался побайтово.

Исправленное рабочее приложение опубликовано в `dist/Switch Lang.app` с прежней подписью. Упакованные self-test и read-only проверка раскладок прошли; штатные проверки, ASan и TSan также проходят (ASan без leak-check). После публикации отдельный повтор вновь завершил 16 из 16 сценариев и восстановил уже исправленный пакет. Один промежуточный повтор остановился на контроле запуска редактора до сценариев исправления: не было ни доставленных клавиш, ни событий адаптера; причина этой нестабильности стенда не установлена. Последний успешный прогон не доказывает отсутствия такой нестабильности.

### Terminal.app

В Terminal воспроизведены два отличия от обычного текстового поля: обе AX-возможности записи равны `false`, а число символов экрана после Backspace может не уменьшаться. Соответствующие проверки заменены узкими правилами для проверенного Apple Terminal. Сейчас сохраняются проверки фокуса, строки, каретки и защиты; суффикс и правый хвост по новому согласованному контракту не читаются. Начальная позиция до набора и запрет удаления за неё защищают от совпадения со старым экранным текстом при невидимом вводе.

До отказа от AX-чтения содержимого на macOS 27.2 / Apple M1 Pro прошли **9 положительных сценариев в настоящем Terminal**: ручная замена в обе стороны, регистр, завершающий пробел, автоматический пробел в обе стороны, Enter, Tab и синтетический Caps с настоящим HID-сбросом. Ещё **2 негативных сценария** подтвердили отказ до первого Backspace исполнителя замены: заранее показанный совпадающий суффикс со скрытым набором; скрытые Backspace ×6 перед таким набором. Содержимое синтетического буфера осталось неизменным, защитная пауза не потребовалась. После изменений также повторно прошли 16 сценариев AppKit.

Для этих проверок в отдельном окне Terminal запускался собственный ограниченный TTY-редактор, который не запускает shell и не выполняет введённые команды. Окно определяется по событию его создания, а не только по списку AX-окон: наблюдался пустой список при существующем фокусе. Настройка теста использует AX-запись только в новом диалоге New Command с выключенным запуском через shell; рабочее приложение AX-текст не записывает. Введённые пользователем команды не читались и не редактировались. Рабочие handler/worker/AX/executor сохранены, отличается только допускающий `nil` proxy диагностический адаптер. Это не физическое нажатие Caps, не проверка исходного session tap и не приёмка всех shell/TUI.

Один дополнительный диагностический запуск завершился SIGSEGV внутри HIServices при доставке AX-уведомления. Тестовый наблюдатель создания окна теперь освобождается после его подтверждения, до запуска worker; в рабочую сборку этот наблюдатель не входит. Последующие положительные и негативные прогоны завершились успешно. Причина SIGSEGV не установлена, поэтому повторные успехи не доказывают отсутствия системной или стендовой нестабильности. После всех диагностических запусков исходный подписанный пакет и настройки восстановлены. Затем исправление Terminal опубликовано в `dist/Switch Lang.app` с прежней постоянной подписью и всеми семью сохранёнными настройками; упакованные self-test, лог-тесты и read-only проверка раскладок прошли. Новый GUI запущен. Проверка физического Caps остаётся открытой.

## Отказ от чтения содержимого приложений

Слово берётся только из ограниченного клавиатурного буфера. AX-граница разрешает только перечисленные метаданные и числовой диапазон строки; чтения содержимого удалены без fallback. В `scripts/test.sh` включена source-policy с пятью самотестами: старый `AXStringForRange`, чтения значений и прямые AX-copy вне этой границы отклоняются. Swift self-test отдельно закрепляет полный разрешённый список метаданных и числовые границы Terminal. Это защита от случайного возврата чтений, не изоляция от намеренного изменения исходников.

На той же macOS 27.2 / Apple M1 Pro прошли штатный набор, release/self-test/logger/read-only раскладки, ASan без leak-check и TSan. В собственном AppKit-редакторе **16 из 16 сценариев** прошли с недоступными `accessibilityValue`, `accessibilitySelectedText`, `accessibilityString(for:)` и `accessibilityAttributedString(for:)`: эти методы всегда возвращают `nil`, числовые метаданные доступны. Точный результат сверяет только сама синтетическая фикстура; рабочее приложение его не читает. Проверены обе стороны, регистр, пробел, Return/Tab/keypad Enter, фокус, readonly, выделение и синтетический Caps с HID-сбросом.

Первый запуск прерван сменой фокуса до доставки клавиш. В следующем прошли контроль и шесть замен, но Return выполнился без исправления; причина пропуска отдельно не установлена. Финальный функциональный тест Enter/Tab добавляет тестовую паузу 100 мс и требует уже опубликованного кандидата перед отправкой действия. Поэтому успешный прогон не подтверждает готовность кандидата при прежнем темпе и не является измерением задержки. Рабочий обработчик и его тайминги не менялись. Диагностика восстановила исходный пакет, семь настроек и исходное закрытое состояние GUI; TCC не сбрасывался.

После удаления чтений повторный прогон на macOS 27.2 / Apple M1 Pro в настоящем Terminal завершил **9 из 9 положительных сценариев**: ручные RU↔EN, регистр и хвостовой пробел; автоматический пробел в обе стороны, Return и Tab; синтетический Caps с подтверждённым HID-сбросом. Ещё **2 из 2 защитных сценариев** скрытого ввода, включая Backspace-компенсацию, отказали до первого Backspace исполнителя: буфер не изменился, пауза не потребовалась. Применён прежний собственный native TTY-редактор без shell; пользовательские команды не читались и не выполнялись. Результаты сохранены в `.tools/terminal-no-text-check`.

Проверена текущая рабочая логика handler/worker/AX/executor с адресным диагностическим адаптером, не физические клавиши и не доставка исходным session tap. Подписанный рабочий пакет и семь настроек восстановлены без изменений. Самостоятельная правка редактора с прежними кареткой и длиной всё ещё может рассинхронизировать клавиатурный буфер и привести к удалению другого текста — этот риск принят пользователем.

Версия без чтения содержимого опубликована в `dist/Switch Lang.app` с прежней постоянной подписью. Упакованные self-test, лог-тесты и read-only раскладки прошли; семь настроек не изменились. Перед публикацией GUI был закрыт и оставлен закрытым. После последующей проверки Terminal рабочее приложение запущено отдельно; новых запросов или сброса TCC не выполнялось.

### Обнаруженные сбои обычной работы

После сообщения пользователя воспроизведён пропущенный сценарий: первая ручная замена проходит, затем Return и отложенное появление следующей строки оставляют новый набор без подтверждённого якоря. Фикстура начинает следующее слово сразу после появления приглашения, без ожидания готовности AX-контекста; следующая замена отказывает с кодом `23`. Это подтверждает пропуск при такой гонке, а не отказ каждой замены после любого Enter. Прежние отдельные сценарии каждый раз сбрасывали контекст и не проверяли непрерывный сеанс. Первое пробное повторное подтверждение метаданных после очистки кандидата не устранило отказ второй замены и отменено. Новое исправление отдельно сохраняет одну позицию, прочитанную на main AX-уведомлением **до** следующей клавиши. Слот вооружается только после очистки tracker и проверки Terminal, не посреди слова. Пока поколение не изменилось, callback читает только числовой диапазон каретки; после начала набора дополнительных чтений нет. Worker принимает снимок один раз перед первой обычной клавишей следующего поколения, проверяет время захвата, тот же безопасный элемент и принадлежность позиции свежей строке, затем учитывает клавишу. Поздний снимок, пропуск поколения, новое поле, навигация и скрытый ввод не дают разрешения на удаление. Таймера и задержки обычных клавиш нет; если позицию не удалось получить до клавиши, сомнительное исправление по-прежнему пропускается. Одного успешного штатного набора недостаточно: он проходил и с отвергнутой первой попыткой. Новый вариант прошёл неизменённый исходный сценарий 2/2 и два независимых запуска постоянной Terminal-регрессии 2/2, без дополнительной паузы между приглашением и набором. Повторно прошли AppKit 16/16 с недоступными текстовыми getters, Terminal 9/9 и оба отказа скрытого ввода без удаления. Успешный Terminal 9/9 дополнительно потребовал восстановления GUI после ошибки аудита: параллельно дописывались только файлы отдельной тестовой фикстуры, не входящие в исполняемую сборку; оригинальный пакет и настройки независимо перепроверены. Штатные, release/layout, ASan без leak-check и TSan проверки прошли. Старые отказы сохранены в `.tools/real-input-failure`, новые результаты — в `.tools/observer-input-fix` и уникальных `.tools/terminal-integration-*`. Дополнительная метадатная трасса показала успешную регистрацию всех пяти AX-уведомлений: события нового приглашения приходят, но пересекаются с началом следующего набора. Отключение проверок поколения или привязка уже начатого слова к позднему якорю не применялись.

Также найдены два SIGSEGV именно рабочего GUI, включая опубликованную версию без чтения содержимого: главный поток падает в `CFDictionaryGetCount` / HIServices `_XXMIGPostNotification`. Это не только прежнее падение диагностической сборки. В исходниках владение подпиской выделено из worker-контекста: `AXObservation` создаёт, регистрирует, отключает и освобождает наблюдатель только на главном потоке, где доставляются уведомления. Worker/listener передают один объединяемый запрос; устаревшая регистрация отменяется, shutdown закрывает публикации до join. Доставка остаётся на main, поэтому ожидание listener не блокирует AX-подтверждение. Source-policy и синтетические lifecycle-регрессии входят в штатный набор. Это устраняет обнаруженное пересечение владения; причинность конкретного системного SIGSEGV не доказана. Шесть синтетических lifecycle-групп проверяют доставку одновременно с запросом teardown, объединение 10 000 запросов, регистрацию при смене запроса, shutdown/restart и подтверждение при ожидающем listener; они прошли также под TSan. Исторические 500 переключений полей не воспроизвели падение и не доказывают устойчивость. Новые интеграционные прогоны не падали; это не гарантия отсутствия системного сбоя. Независимое статическое ревью подтверждённых дефектов не нашло. Физические клавиши и исходный session tap по-прежнему не проверены.

Исправления опубликованы в `dist/Switch Lang.app` с прежней постоянной подписью; семь настроек сохранены, GUI запущен. Уже опубликованный обычный GUI выдержал ещё 500 переключений полей собственного AppKit-редактора без изменения handler, публикации клавиш и чтения содержимого. Пакет и настройки после этого независимо сверены; отсутствие падения в ограниченном тесте не доказывает длительную устойчивость.
